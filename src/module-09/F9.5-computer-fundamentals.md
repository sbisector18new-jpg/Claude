## 1. Session 1 — What a Computer Is ★★★☆☆

A **computer** is an electronic device that accepts **data** as input, **processes** it according to
stored instructions, **stores** it, and produces **information** as output.

**Data** are raw facts; **information** is processed, meaningful data. The distinction is examined.

**Characteristics:** speed, **accuracy**, **diligence** (no fatigue), versatility, storage — and no
intelligence of its own, which is the point of **GIGO: garbage in, garbage out**.

### 1.1 The generations

| Generation | Technology | Examples |
|---|---|---|
| **First** | **Vacuum tubes** | ENIAC, UNIVAC |
| **Second** | **Transistors** | — |
| **Third** | **Integrated circuits (IC)** | — |
| **Fourth** | **Microprocessors**, VLSI | Personal computers |
| **Fifth** | **Artificial intelligence**, ULSI | — |

::: must-master | MUST MASTER · THE GENERATION SEQUENCE, AND BABBAGE
**Vacuum tube » transistor » integrated circuit » microprocessor » artificial intelligence.** Five stages,
in that order, and any of them can be asked by number.

The two most-asked: **third generation = integrated circuit**, **fourth generation = microprocessor**.

**Charles Babbage** is called the **father of the computer**, for the Difference Engine and Analytical
Engine. **Ada Lovelace** is regarded as the first programmer.
:::

**Types by capacity:** supercomputer (India's include the PARAM series) » mainframe » mini » micro or
personal computer. By data handling: analog, digital and hybrid.

## 2. Session 2 — The CPU and Its Registers ★★★★★

### 2.1 The three parts of the CPU

| Part | Function |
|---|---|
| **ALU** — Arithmetic and Logic Unit | Performs **arithmetic and logical** operations |
| **CU** — Control Unit | **Directs and coordinates** all operations; fetches and decodes instructions |
| **Registers** | Very small, very fast storage **inside** the CPU |

The CPU is often called the **brain of the computer**. The ALU and CU together with registers form the
processor.

### 2.2 The machine cycle

> **FETCH » DECODE » EXECUTE » STORE**

The order is asked, and it is the only sensible one: you cannot decode an instruction before fetching it.

### 2.3 The registers — the 2023 item

::: must-master | MUST MASTER · WHAT EACH REGISTER HOLDS
This is a 2023 question, and the registers are only distinguishable by **what they hold**.

| Register | What it holds |
|---|---|
| **Program Counter (PC)** | The **address of the NEXT instruction** to be executed |
| **Instruction Register (IR)** | The instruction **currently being executed** |
| **Memory Address Register (MAR)** | The **address** of the memory location to be accessed |
| **Memory Buffer Register (MBR)** | The **data** being transferred to or from memory |
| **Accumulator (AC)** | **Intermediate arithmetic results** |

The distinction that decides the question: **the Program Counter holds an ADDRESS, and it is the address
of the NEXT instruction — not the current one.** The register holding the current instruction is the
**Instruction Register**.

Both halves are traps. An option saying the program counter holds the *current* instruction is wrong on
both counts — wrong register and wrong kind of content.
:::

**Buses** connect the parts: the **data bus** carries data, the **address bus** carries addresses, and the
**control bus** carries control signals.

## 3. Session 3 — The Memory Hierarchy ★★★★★

### 3.1 The hierarchy, fastest first

> **Registers » Cache » Main memory (RAM) » Secondary storage (hard disk, SSD, optical)**

As you move down: **speed decreases, capacity increases, cost per byte decreases**. All three trends move
together, which makes the hierarchy easy to reconstruct.

**Cache** sits **between the CPU and main memory** and is faster than RAM. It comes in levels — L1, L2,
L3 — with L1 the smallest and fastest.

### 3.2 RAM and ROM

::: must-master | MUST MASTER · VOLATILE VERSUS NON-VOLATILE
| | **RAM** | **ROM** |
|---|---|---|
| Full form | Random Access Memory | Read Only Memory |
| **Volatility** | **VOLATILE** — contents lost when power goes | **NON-VOLATILE** — contents retained |
| Access | **Read and write** | **Read only** |
| Purpose | Working memory for running programs | Stores the **BIOS or firmware** |

**RAM is volatile; ROM is non-volatile.** That single pair answers a large share of memory questions, and
the wrong option is almost always the reversal — "ROM is volatile memory".

**Two types of RAM:**

| | **SRAM** (static) | **DRAM** (dynamic) |
|---|---|---|
| Refreshing | **Not needed** | **Needs periodic refreshing** |
| Speed and cost | **Faster, costlier** | Slower, cheaper |
| Used as | **Cache** | **Main memory** |

**Types of ROM:** **PROM** — programmable once. **EPROM** — erasable by **ultraviolet light**.
**EEPROM** — **electrically** erasable.
:::

### 3.3 Units of storage

| Unit | Size |
|---|---|
| **Nibble** | **4 bits** |
| **Byte** | **8 bits** |
| **Kilobyte (KB)** | **1,024 bytes** — that is 2¹⁰, not 1,000 |
| Megabyte, Gigabyte, Terabyte | Each 1,024 of the previous |

Beyond terabyte: petabyte, exabyte, zettabyte, yottabyte.

## 5. Session 5 — Number Systems ★★★★★

**Two 2023 questions came from this section**, and it is the most mechanical topic in the entire syllabus.
Learn the two grouping rules and the marks are guaranteed.

### 5.1 The four systems

| System | Base | Digits used |
|---|---|---|
| **Binary** | **2** | 0, 1 |
| **Octal** | **8** | 0 to 7 |
| **Decimal** | **10** | 0 to 9 |
| **Hexadecimal** | **16** | 0 to 9, then **A B C D E F** |

::: must-master | MUST MASTER · THE HEXADECIMAL LETTERS STOP AT F
**A = 10, B = 11, C = 12, D = 13, E = 14, F = 15.**

**F is 15, not 16**, because the digits of base 16 run from 0 to 15 — there are sixteen of them, and the
sixteenth is 15. And the letters run **A to F**, not A to G. Both errors are offered as options.
:::

### 5.2 The grouping rule — the whole trick

::: must-master | MUST MASTER · THREE FOR OCTAL, FOUR FOR HEXADECIMAL
Because 8 = 2³ and 16 = 2⁴:

- **Each OCTAL digit is exactly THREE binary digits**
- **Each HEXADECIMAL digit is exactly FOUR binary digits**

So converting between binary and octal or hexadecimal requires **no arithmetic at all** — only grouping,
**always from the right**, padding the leftmost group with zeros if needed.

| Octal | Binary | | Hex | Binary |
|---|---|---|---|---|
| 0 | 000 | | 0 | 0000 |
| 1 | 001 | | 5 | 0101 |
| 2 | 010 | | 9 | 1001 |
| 5 | 101 | | A | 1010 |
| 7 | 111 | | D | 1101 |
| | | | F | 1111 |

**This is why octal and hexadecimal exist**: they are compact ways of writing binary that a human can
read, and the conversion is free.
:::

### 5.3 Worked conversions

**Octal to binary** — the 2023 item. Replace each digit with its three bits:

> **725 in octal.** 7 » 111 · 2 » 010 · 5 » 101
> Answer: **111 010 101**

**Binary to octal.** Group in threes from the right:

> **110110.** » 110 | 110 » 6 | 6 » **66 in octal**

**Binary to hexadecimal.** Group in fours from the right:

> **11011010.** » 1101 | 1010 » D | A » **DA in hexadecimal**

**Hexadecimal to decimal** — the other 2023 item. Multiply each digit by its positional power of 16:

> **2F.** = (2 × 16) + (15 × 1) = 32 + 15 = **47**
> **1A.** = (1 × 16) + (10 × 1) = 16 + 10 = **26**

**Binary to decimal.** Add the positional weights where the bit is 1:

> **101101.** = 32 + 8 + 4 + 1 = **45**
> (weights from the right: 1, 2, 4, 8, 16, 32)

**Decimal to binary.** Divide repeatedly by 2 and read the remainders **upwards**:

> **25.** 25÷2 = 12 r **1** · 12÷2 = 6 r **0** · 6÷2 = 3 r **0** · 3÷2 = 1 r **1** · 1÷2 = 0 r **1**
> Reading upwards: **11001**

::: memory | MEMORY TECHNIQUE · CHECK EVERY CONVERSION IN FIVE SECONDS
Two habits that make errors nearly impossible:

1. **Group from the RIGHT, never the left.** The rightmost bit is the units bit, so grouping must start
   there. Grouping from the left is the single commonest mistake, and it gives an answer that looks
   plausible
2. **Sanity-check the magnitude.** A two-digit hexadecimal number lies between 0 and 255. So hex 2F
   cannot be 215 — that would need the first digit to be D. If your answer is out of range, you have
   multiplied by the wrong power

For decimal-to-binary, the reverse check takes five seconds: 11001 = 16 + 8 + 1 = 25. Always do it.
:::

## 6. Session 6 — Codes and Logic Gates ★★★☆☆

### 6.1 Character codes

| Code | Bits | Characters |
|---|---|---|
| **ASCII** | **7 bits** standard; 8 bits extended | 128; 256 extended |
| **Unicode** | 16 bits and more | Covers most of the world's scripts |
| EBCDIC | 8 bits | An IBM mainframe code |
| BCD | 4 bits per digit | Binary coded decimal |

### 6.2 Logic gates

**Basic gates:** **AND** (output 1 only if all inputs are 1) · **OR** (output 1 if any input is 1) ·
**NOT** (inverts).

**Derived gates:** **NAND**, **NOR**, **XOR**, XNOR.

::: must-master | MUST MASTER · NAND AND NOR ARE THE UNIVERSAL GATES
**NAND and NOR are called universal gates**, because either one alone can be used to build every other
gate — AND, OR and NOT included.

The question is usually "which of the following is a universal gate", with AND, OR and NOT as
distractors. **The basic gates are not universal; the two derived ones are.** That inversion is the whole
point of the question.
:::

## 10. Five-Minute Wall Sheet

::: session | FIVE-MINUTE WALL SHEET · CHAPTER F9.5
**OCTAL = 3 BITS · HEX = 4 BITS · GROUP FROM THE RIGHT**

**A=10 B=11 C=12 D=13 E=14 F=15** — letters stop at F

**HEX TO DECIMAL: × 16 THEN ADD** — 2F = 32 + 15 = 47 · 1A = 16 + 10 = 26

**BINARY WEIGHTS FROM THE RIGHT: 1 2 4 8 16 32 64 128**

**DECIMAL TO BINARY: DIVIDE BY 2, READ REMAINDERS UPWARD**

**RAM VOLATILE · ROM NON-VOLATILE (BIOS)**

**SRAM = CACHE, NO REFRESH · DRAM = MAIN MEMORY, NEEDS REFRESH**

**REGISTER » CACHE » RAM » DISK**

**PROGRAM COUNTER = NEXT INSTRUCTION'S ADDRESS · INSTRUCTION REGISTER = CURRENT INSTRUCTION**

**FETCH » DECODE » EXECUTE » STORE**

**NIBBLE 4 · BYTE 8 · KB 1,024**

**GEN 3 = IC · GEN 4 = MICROPROCESSOR**

**MICR = CHEQUES · OMR = MARKS · OCR = CHARACTERS**

**ASCII = 7 BITS = 128 CHARACTERS**

**NAND AND NOR ARE UNIVERSAL**

**ONE LINE FOR THE INTERVIEW** Octal and hexadecimal exist because 8 and 16 are exact powers of two, so
each digit maps onto exactly three or four bits — which lets a human read a binary value compactly
without any arithmetic at all.
