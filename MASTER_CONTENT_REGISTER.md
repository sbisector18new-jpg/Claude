**114 pages, 125 questions.** The module is deliberately split into **a method that does not decay and
dossiers that do**, and the split is the whole design:

- **F10.1** carries the **collection system** (a one-page-a-month register whose third column records which
  module an item attaches to — an item that attaches to nothing is discarded), the **report-to-publisher
  table**, which is permanently askable and permanently learnable, and the **twelve-item verification
  sweep** to be run in the fortnight before the paper
- **F10.2** carries the perishable content, every figure dated and sourced, with the labour codes and the
  EPFO items first because they are directly on the subject matter of the post

**The classification in F10.1 §1.1 is the load-bearing idea:** current affairs questions are of three kinds
— **institutional attribution** (permanent), **a recent definite change** (decays slowly), and **a current
reading** (decays in months). Candidates spend their time on the third, which is the least asked. The
recommended split of the twelve hours is **four hours on attributions, six on recent definite changes, two
on the sweep** — not twelve on chasing the news.

**F10.2 §2.2 introduces a discipline worth preserving:** reporting does not distinguish between
**proposed, departmentally approved, Cabinet approved and notified**, and an examiner does. **Only the last
is law.** The EPF wage ceiling is the live example — still ₹15,000, with ₹25,000 approved but unnotified —
and Q27 of that chapter turns on it.

#### 3.5.1 The twelve-month dossier — F10.3 and F10.4

**Scope: August 2025 to a cut-off of 1 August 2026.** Every item carries an inline source link. Three
conventions were fixed when it was written and should be preserved:

1. **The cut-off is applied strictly and straddles are declared.** The Commonwealth Games closed on
   **2 August 2026**, one day outside, and F10.4 §5.2 says so rather than rounding. NISAR launched on
   **30 July 2025**, two days before the window opens, and F10.4 §3.1 marks it as a preceding anchor
2. **Weighting follows F10.1 §1.2, not the news cycle.** F10.3 §1 — labour, social security and the EPFO —
   is the longest section in the dossier. F10.4 is arranged in **descending order of yield**, and its §5
   (awards, sport, persons) is compact **by decision**, with the reasoning restated in F10.4 §0. **Deaths
   are not tabulated at all**, because obituaries attach to nothing in the static syllabus
3. **Where sources disagree, the dossier records what they agree on.** F10.3 §3.3 gives the winner of each
   2026 State election but **withholds the seat counts**, because reputable outlets differ on Tamil Nadu and
   Puducherry; a note explains the omission rather than concealing it. Similarly F10.4 §2.3 flags five index
   rankings as coming from a **coaching compilation rather than the publishing bodies**, and **no question is
   built on them**

**The single most valuable item in the dossier for this post** is F10.3 §1.3: **EPFO officers, including
Assistant Provident Fund Commissioners, have been notified under Chapter III of the Code on Social Security,
2020, and appointed Recovery Officers.** The APFC's statutory powers of inquiry and recovery now flow from
the Code rather than from the 1952 Act directly, that Act having been subsumed into it. That is a better
interview answer than reciting Section 7A, and it is recorded here so that a later sitting does not lose it.

**Second most valuable:** F10.3 §1.5 on the **India–UK Double Contributions Convention**, in force 15 July
2026 — a social security agreement the **EPFO itself administers**, with a **60-month** detachment exemption,
coordinating **contributions and not benefits**.

## 8. Build pipeline

Established at the first sitting. `src/` is the source of truth per §6.

| Path | Role |
|---|---|
| `src/**/*.md` | **Master manuscript.** Markdown with front matter and `:::` callout blocks |
| `build/build.py` | Converter. **Python 3 stdlib only** — no third-party packages |
| `build/style.css` | Typography, callout variants, A4 print rules |
| `build/pdf.mjs` | **PDF renderer.** Drives the bundled Chrome over the DevTools Protocol. No npm packages |
| `build/check.py` | **Quality gate.** Run before every commit — see §8.4 |
| `build/shot.mjs` | Screenshot helper, for verifying layout and glyph rendering |
| `docs/**/*.html` | **Generated. Never edit by hand.** |
| `pdf/**/*.pdf` | **Generated.** A4, running header, "Page X of Y" footer |

```sh
python3 build/build.py                     # src/*.md   -> docs/*.html
env -u NODE_OPTIONS node build/pdf.mjs     # docs/*.html -> pdf/*.pdf
```

`env -u NODE_OPTIONS` is required: the environment sets
`NODE_OPTIONS=--require /opt/amazon/kiro-agent/proxy-bootstrap.js`, and that file does not exist, so
every plain `node` invocation dies with `MODULE_NOT_FOUND`.

### 8.1 How PDF generation works, and why it took a detour

There is **no** PDF toolchain here — no `pandoc`, `weasyprint`, `wkhtmltopdf` or LaTeX — and PyPI is
blocked (`403` through the proxy), so `reportlab` and `weasyprint` cannot be installed. My first
answer was that PDFs were impossible and the user should print from a browser. That was wrong.

**Chrome for Testing 151 is installed** at `/usr/local/bin/chrome`, and Node 22 ships a global
`WebSocket`. So `build/pdf.mjs` launches Chrome headless with a debugging port and calls
`Page.printToPDF` over CDP. This renders the real stylesheet and, unlike `chrome --print-to-pdf`,
supports `headerTemplate`/`footerTemplate` — which is where the page numbering comes from.

`@playwright/mcp` is installed but the Playwright **library** is not, so the CDP route is necessary
rather than merely preferred.

### 8.2 The font problem, and the fix

The only font family installed is **Noto Sans** (every weight and width, no other family). It has no
glyph for several characters the manuscript uses, so they printed as blank boxes:

| Character | Count in sources | Handling |
|---|---:|---|
| ★ ☆ priority ratings | 85 | **Drawn in CSS** with `clip-path`, so they stay real stars |
| → ← | 35 | Substituted with `»` `«` |
| ↑ ↓ | 29 | Substituted with `(+)` `(−)` |
| ⊂ ≈ ≠ | 5 | Substituted with words |

Substitution happens in `build.py` on the way out to HTML, so **the Markdown sources keep the proper
characters**. Verified: zero unrenderable codepoints remain in `docs/`.

`₹`, `—`, `·`, `§`, `−`, `…`, `÷` are all covered by Noto Sans and pass through untouched.

There is **no serif font** on the system, so headings fall back to Noto Sans rather than the serif in
the original PDFs. Cosmetic only, and it corrects itself on any machine with a serif font installed.

The substitution map was extended while writing F6.8: **≥ ≤ √ ∞ ∑** are also absent from Noto Sans.
Note the odd case — Greek capital sigma **Σ** (U+03A3) *is* present while the n-ary summation **∑**
(U+2211) is not, so the build maps one to the other. Greek σ, μ and ρ, the superscript two, ± and × are
all fine.

**Extended again while writing Modules 4, 10 and 11**, after a glyph audit found two characters that had
been shipping as blank boxes. The map now also covers:

| Character | Substitution | Note |
|---|---|---|
| **✓ ✗** (U+2713, U+2717) | `yes` / `no` | **Were live in F6.4 and printing as blank boxes** |
| **∓** (U+2213) | `-/+` | Caught in draft in F8.7 before it shipped |
| ∠ ∴ ⇒ ≡ ∈ △ | words or `=` | Added pre-emptively; none is in Noto Sans |

**Verified PRESENT and passed through untouched:** **π**, the degree sign, all superscripts and subscripts
(U+2070–U+2085, U+00B2, U+00B3, U+00B9), vulgar fractions (½ ¼ ¾ ⅓ ⅔ ⅛ ⅕ ⅝), the fraction slash U+2044,
prime U+2032, ± × ÷ − and Greek. Modules 4 to 11 use 52 distinct non-ASCII codepoints and all 52 render.

**One consequence for authoring.** Because √ is substituted with the literal string `sqrt`, `√3` renders as
`sqrt3`, which reads badly in a formula-dense chapter. **F8.6 therefore writes surds as words — "root 3" —
and F4.x follows the same practice.** The alternative would be to change the substitution, which would
break F9.1's existing usage.

### 8.4 The quality gate

1. Question numbering contiguous from 1
2. An answer row for every question

   score by elimination and trains the wrong instinct
4. **Section-heading numbering contiguous** — this caught a real defect immediately, F6.4 having jumped
   from section 5 to section 7
5. No unrenderable codepoints surviving into the built HTML

**The keys are planned before the options are written, not rebalanced afterwards.** This matters: the gate
tolerates a spread of only `max(2, n/8)` between the most and least used letter, so a 20-question chapter
must come in within 2. Assigning the 20 letters up front and then constructing each question to put its
correct answer at the assigned position is the only method that reliably passes on the first build.
Retro-fitting a skewed key means rewriting option sets, which risks breaking the explanations.

::: note | NOTE · WHAT THE GATE DOES NOT CHECK, AND HOW MODULE 8 WAS VERIFIED INSTEAD
`check.py` verifies that a key is **balanced and complete**. It cannot verify that a key is **correct** —
that the letter recorded is the letter of the true answer. For prose questions that has to rest on
authorship; for quantitative ones it does not.

So every numerical answer in **F8.5 to F8.8** was **recomputed independently in Python** — 99 distinct
claims across percentages, ratios, averages, alligation, mensuration, discriminants, combinatorics,
remainders and the four DI data sets — and checked against the recorded key. All 99 matched. The
qualitative DI answers (fastest-growing office, lowest settlement rate, highest default count) were
confirmed the same way.

**Modules 4, 10 and 11 introduced a different verification problem: currency rather than arithmetic.**
Their answers depend on facts about the world in 2026, and a plausible-sounding wrong figure is not
detectable by any script. So **every dated fact in those modules was taken from a primary or reputable
secondary source at the time of writing, and the source is linked inline in the chapter** — the labour
codes' commencement, the EPF interest rate, the EPS 2026 replacement, EPFO 3.0's limits, the ELI Scheme's
terms, the GST restructuring, the Income-tax Act 2025, the Sixteenth Finance Commission, the Budget and
Survey figures, the repo rate, the PLFS readings, the fertility crossing and the Census 2027 schedule.

**Sourcing is a weaker guarantee than recomputation, and the register should say so.** The dated-figure
convention and F10.1 §4's twelve-item sweep exist precisely because that guarantee expires. **Every
`[AS AT 16 AUG 2026]` figure must be re-verified before the paper**, and the sweep is the checklist for
doing it.

Two further audits were run beyond the gate. **A full glyph audit** across the built HTML enumerated every
non-ASCII codepoint and tested each against `fc-list`, rather than against `check.py`'s fixed list. That is
how `∓` (U+2213) was caught in F8.7 before it shipped, and how **`✓` and `✗` were found to have been
printing as blank boxes in F6.4 since Module 6 was written** — both absent from Noto Sans *and* absent from
`build.py`'s substitution map, so the old gate passed them.
:::

### 8.4.1 The gate now checks font coverage dynamically

**`check.py`'s glyph check was rewritten this sitting**, because the manual audit above had to be run by
hand and a fixed list of known-bad codepoints cannot catch a character nobody anticipated.

`discover_unrenderable()` now collects **every non-ASCII codepoint that actually appears in the built
HTML** — stripping the embedded `<style>` block first — and asks **fontconfig** about each one. The fixed
`UNRENDERABLE` set is retained as a **floor**, and if `fc-list` is unavailable the check degrades to the
previous behaviour rather than failing.

**The result: a character absent from the installed fonts can no longer reach a PDF as a blank box**, whether
or not anyone remembered to add it to the substitution map. Run against the repository before the fix, the
new check failed F6.4 immediately and named the two characters. The old convention — *check any new symbol
with `fc-list ":charset=XXXX"` before using it* — is still good practice, but it is no longer the only line
of defence.

Stdlib only, per §8's constraint: `subprocess` is stdlib, and no third-party package was added.
